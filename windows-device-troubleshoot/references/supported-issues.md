| 码 | 含义 | 常见真实原因 | 是否值得继续排障 |

| 18 / 28 | 需重装 / 未安装 | INF 缺失、安装中断 | 是 |
| 31 | 服务创建失败 | 服务键冲突、文件缺失 | 是 |
| 37 / 39 / 41 | 加载或卸载失败 | 驱动损坏、残留服务 | 是 |
| 43 | 驱动报告设备故障 | 固件、硬件接触、USB 供电 | 是，优先断电重置 |

## 三、按成因层索引

### 策略层（最容易被漏掉的一层）

触发条件：换任何版本驱动都报同一错误码，且往往只有一两个设备异常。

检查清单：

1. VBS / 内核隔离是否在最近一次启动被启用
2. 是否有累积更新在故障前安装、在故障时首次重启生效
3. `VulnerableDriverBlocklistEnable` 是否为 1
4. `driversipolicy.p7b` 内是否有该厂商条目（注意 UTF-16 编码）
5. 是否存在设备安装限制策略、Smart App Control

处置：关闭对应策略后重启验证，并提供还原脚本。修改启动配置前必须确认 BitLocker 状态。

### 冲突层

常见来源：抓包驱动（Npcap）、虚拟机桥接（VMware Bridge）、杀毒软件的过滤驱动、游戏反作弊驱动。

判据：安全模式下设备恢复正常。处置：逐个解绑，用二分法定位。

### 硬件层

判据三条同时成立即可判定：

1. 网口灯（或设备指示灯）完全不亮
2. 断电重置后无变化
3. 安全模式下仍报同一错误码

此时停止软件排查，改走售后或外接替代方案。继续折腾软件不会有结果。

## 四、明确的非目标

本技能**不处理**以下情况，遇到应直接给出别的路径：

- 需要拆机、更换硬件的物理损坏
- 网络能连通但上不了网（DNS、代理、路由、带宽问题）——那是网络配置，不是设备故障
- 驱动开发、签名申请、WHQL 认证流程
- macOS / Linux 下的设备问题
